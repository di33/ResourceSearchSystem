# 游戏资源用途分类规则（版本 game_resource_usage_v1.1）

## 目标

请根据资源导入游戏后的空间使用形态和直接用途，为资源填写 `classification`。

分类只表达“这个资源在游戏里怎么被使用”，不表达对象名称、主题、风格、颜色、材质、时代、具体内容、文件格式或制作工具。这些信息应写入描述，不应写成用途分类。

## 输出字段

- `space`：空间使用形态，只能选一个。
- `category`：用途大类，只能选一个。
- `subcategories`：用途小类，可以多选，但只选直接包含的粗粒度用途，通常不超过三个。
- `reason`：一句话说明分类依据。
- `suggestion`：只有选择大类“其他”或任一小类“其他”时填写；否则为 `null`。

## 空间使用形态

- `2D`：资源直接用于平面图像、二维坐标、二维动画、Sprite、角色立绘、像素角色、序列帧、Tilemap/Tileset、二维背景、UI 或二维特效。三维软件预渲染成图片仍归 2D。
- `3D`：资源直接用于三维几何、三维骨骼、三维空间结构、三维模型、骨骼动画、三维地形、PBR 材质、Skybox 或三维粒子。正交、俯视、横版相机不改变 3D 判断。
- `通用`：资源本身不依赖二维或三维空间，可不改变结构直接服务于多种空间形态。典型是字体和音频。不要因为普通 PNG 理论上能贴到模型上就判为通用。
- `混合`：当前分类单位不能拆分，并且同时包含可独立使用的 2D 与 3D 内容。
- `不确定`：信息不足、缺少预览、无法解析或证据不可靠，无法判断空间形态。

## 用途大类和小类

### 角色

用于承担角色身份的主体，或构成、驱动、表现角色的资源。角色强调“谁在行动或被控制”，不是普通场景物体。

- `人物`：人类、类人角色、NPC、主角、敌方人形单位。
- `动物`：真实或拟真的动物角色，例如鸟、狼、马、鱼。
- `怪物`：幻想生物、敌怪、Boss、异形生物等非普通动物角色。
- `机器人`：机器人、无人机、机械生命体等以机械智能体身份出现的角色。
- `机甲`：大型可驾驶或拟角色化的机械装甲、战斗机甲。
- `角色部件`：头部、手臂、翅膀、身体部件、装备在角色身上的身体组件。
- `服装`：衣服、护甲外观、角色穿戴外观，不含作为独立道具展示的普通装备。
- `动作`：角色动作、动画、姿态、攻击动作、移动动作、骨骼动作数据。
- `表情`：脸部表情、情绪表情、表情图集、口型等角色表情资源。
- `其他`：确属角色用途但以上小类都无法表达。

### 环境

用于构成游戏世界、场景空间、地貌、建筑、自然环境和视觉背景。环境强调“空间本身”，不是放在空间里的独立物件。

- `建筑与结构`：房屋、城堡、桥梁、墙体、平台、门廊、塔楼、结构件。
- `地形`：地面、岩石地表、山体、洞穴地貌、瓦片地形、可行走地表。
- `自然景观`：山川、云、远景、自然背景元素，不特指植被、水体或天空时使用。
- `植被`：树、草、灌木、花、藤蔓、森林植被。
- `水体`：河流、湖泊、海面、瀑布、水面、液体场景元素。
- `天空`：天空盒、天空背景、云层天空、星空、日月天空元素。
- `道路`：道路、轨道、路径、桥面、赛道、路面标记。
- `室内场景`：房间、室内背景、室内结构组合、室内环境套件。
- `场景背景`：不可交互或主要作为后方视觉背景的背景图、远景图、横版背景。
- `其他`：确属环境用途但以上小类都无法表达。

### 界面

用于屏幕空间交互、信息展示、状态反馈、菜单系统或操作引导。界面强调“玩家在屏幕 UI 中看到或点击”，不是游戏世界中的实体。

- `图标`：技能图标、物品图标、状态图标、货币图标、头像图标等小型符号。
- `按钮`：可点击按钮、按钮状态、按钮皮肤、确认/取消按钮。
- `面板`：信息面板、背包框、窗口底板、UI 容器。
- `菜单`：主菜单、暂停菜单、选项菜单、关卡选择菜单。
- `弹窗`：对话框、提示窗、确认弹窗、奖励弹窗。
- `HUD`：战斗界面、屏幕常驻信息层、准星、小地图框、游戏内状态显示组合。
- `状态条`：生命条、魔法条、进度条、经验条、冷却条。
- `输入控件`：输入框、滑块、复选框、开关、选择控件。
- `提示`：教程提示、操作提示、警告提示、引导箭头、提示标签。
- `其他`：确属界面用途但以上小类都无法表达。

文件名中的 `right`、`wrong`、`appear`、`blank` 等状态词可能只是图标状态或 UI 动画帧，不足以证明资源是角色动作。数字、徽章、笔记、标记、圆形符号、状态符号等小型符号即使带这些状态词，仍应按可见用途归入界面，通常是 `界面-图标`；如果它本身是 UI 动画反馈，可归 `界面-界面特效`。

### 物件

可作为独立对象放入游戏世界，但不是角色、环境主体、界面或特效。物件强调“空间中的东西”。

- `道具`：钥匙、药水、金币、宝箱、书、瓶子、拾取物等游戏道具。
- `装备`：盔甲、盾牌、饰品、可装备物，不含只作为 UI 图标的装备图片。
- `武器`：剑、枪、弓、法杖、炮、投掷武器等用于攻击的物体。
- `载具`：车、船、飞机、坐骑载具、可驾驶机器。
- `家具`：桌、椅、床、柜、灯具、室内摆放家具。
- `机关`：开关、陷阱、尖刺、门控、传送器、机关装置等带危险、触发或状态变化功能的世界对象。
- `可交互物`：可点击、可拾取、可打开、可破坏或可触发的世界对象。
- `摆件`：装饰物、静态陈设、无明显交互功能的独立物体。
- `其他`：确属物件用途但以上小类都无法表达。

独立物件的状态帧仍优先保持为物件。例如瓶子、箱子、门、机关、容器、可拾取物的 `open`、`opening`、`closed`、`closing`、`appear`、`disappear`、数量变化或破损状态，通常归 `物件-道具`、`物件-可交互物`、`物件-机关` 或 `物件-摆件`，不要仅因它是动画帧就改归特效。

### 特效

用于短暂、动态或持续的视觉反馈。特效按使用时机和功能分类，不按火焰、烟雾、冰霜、雷电、魔法等视觉内容分类。

- `环境特效`：雨雪、雾、落叶、流水光效、环境粒子、场景氛围特效。
- `技能与攻击特效`：施法、攻击、爆炸、斩击、能量释放、魔法效果。
- `弹道特效`：子弹、箭矢、飞弹、激光束、投射物轨迹。
- `命中特效`：击中、受击、碰撞、伤害反馈、暴击闪光。
- `状态特效`：中毒、燃烧、护盾、增益、减益、持续状态表现。
- `界面特效`：UI 闪光、按钮反馈、奖励弹出特效、界面粒子。
- `转场特效`：淡入淡出、场景切换、关卡转场、镜头过渡效果。
- `其他`：确属特效用途但以上小类都无法表达。

不要把“独立物件的开合、状态切换或数量变化帧”当作特效；只有画面主体主要是粒子、光效、爆炸、烟雾、拖尾、冲击、闪光或没有稳定物件主体的动态视觉反馈时，才优先归入特效。

### 文字与字体

主要价值是提供字体、字形或可独立使用的设计文字。写有“开始”的按钮仍归界面-按钮；字体文件或字形集归文字与字体。

- `字体`：TTF、OTF、字体文件、可安装字体。
- `字形集`：Bitmap Font、字符图集、字体贴图、字形纹理。
- `标题字`：标题 Logo 字、章节标题字、装饰性大字。
- `数字字形`：分数字体、伤害数字、计时数字、数字贴图。
- `其他`：确属文字与字体用途但以上小类都无法表达。

### 音频

主要价值是提供游戏中的声音内容。音频通常使用 `space=通用`。按声音在游戏中的直接用途分类，不按文件格式、音色风格或音乐流派分类。

- `音乐`：BGM、主题曲、循环配乐、关卡音乐、战斗音乐。
- `环境声`：风雨、水流、森林、城市、人群、机器环境氛围声。
- `界面音效`：点击、确认、取消、菜单切换、提示弹出等 UI 声音。
- `战斗音效`：攻击、命中、爆炸、武器、受击、战斗反馈声音。
- `技能音效`：施法、技能释放、能量聚集、魔法触发、特殊能力声音。
- `交互音效`：拾取、开门、开箱、机关触发、脚步、跳跃、移动交互声音。
- `角色语音`：台词、喊叫、对白、角色反应、人声表演。
- `音效`：用途可确定为 SFX，但无法进一步判断属于哪种音效。
- `其他`：确属音频用途但以上小类都无法表达。

### 其他

用于收纳占位/辅助资源，或七个正式内容大类都无法表达直接用途的资源。

- `占位/辅助资源`：完全透明、无可见像素、None 空图层、空白占位、全黑/全白占位图、遮罩、填充图块、调试或资源管线辅助素材。该小类不需要填写 `suggestion`。
- `其他`：确实无法归入任何现有大类或小类时使用。选择该小类必须填写 `suggestion`，提出可复用的新分类建议。

## 边界规则

- 先使用现有分类。现有分类能表达直接用途时，不得选“其他”，不得新增分类。
- 如果已经选择了明确小类，不得同时选择“其他”；“其他”只在没有任何明确小类适用时单独使用。
- 选择 `其他-占位/辅助资源` 时不需要填写 `suggestion`；选择小类“其他”时必须填写 `suggestion`。
- “不确定”只用于 `space` 证据不足；它不是 `category`，也不表示分类体系缺项。
- 陷阱、尖刺、开关、门控、传送器等带危险、触发或交互功能的世界对象，优先归入 `物件-机关` 或 `物件-可交互物`；不要仅因它们放在场景中就归入 `环境-场景背景`。
- `right`、`left`、`appear`、`disappear`、`open`、`opening`、`closed`、`closing`、`wrong` 等文件名状态词只能作为弱线索；不要仅凭这些词把资源归入 `角色-动作`。必须看到明确角色身体、角色部件、角色姿态或角色动画，才归角色动作。
- 数字、徽章、笔记、标记、圆形符号、状态符号等 UI 图标，即使带有 `appear`、`right`、`wrong` 等状态名，也优先归 `界面-图标` 或 `界面-界面特效`。
- 瓶子、箱子、门、机关、容器等独立物件的打开、关闭、出现、消失、数量变化或状态帧，优先保持为 `物件-道具` / `物件-可交互物` / `物件-机关`；只有画面主体主要是粒子、光效、爆炸、拖尾、冲击或没有稳定物件主体时才归 `特效`。
- 完全透明、无可见像素、None 空图层、空白占位图、全黑或全白占位/遮罩/填充图块，归入 `其他-占位/辅助资源`；其他颜色的纯色图块交给模型根据可见内容与上下文判断。
- 不要把门、钥匙、金币、宝箱、瓶子、蜡烛、桌子、剑、松树等具体对象新增为分类。
- 不要把火焰、烟雾、冰霜、雷电、魔法、红色、破旧、中世纪、科幻、卡通、像素风等内容、主题、颜色或风格新增为分类。
- 不要把 PNG、WAV、FBX、Unity、Godot、RPG Maker、PBR、像素、分辨率、视角等格式、工具、技术或表现方式混入用途分类。

## suggestion 字段

只有选择小类“其他”时填写；否则为 `null`。`其他-占位/辅助资源` 是已定义小类，不需要 suggestion。

`suggestion` 必须包含：

- `level`：大类或小类。
- `parent_category`：小类所属大类；大类建议可为空。
- `name`：建议分类名称。
- `definition`：定义。
- `include_scope`：包含范围。
- `exclude_scope`：排除范围。
- `relation_to_existing`：与现有分类的关系。
- `examples`：示例资源。
- `search_value`：对检索的价值。
- `affected_resources`：可能受影响的资源范围。
